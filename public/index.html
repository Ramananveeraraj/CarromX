Relational Database Entity-Relationship Diagram (ERD)

Mandatory relational architecture powering CarromX tournament workflows.

schema.sql (PostgreSQL & SQLite) 
[USERS] 1 ────────────────────────< [TOURNAMENTS] (Hosted by organizer)
  │                                        │
  │ (Plays in)                             │ (Configures)
  ▼                                        ▼
[PARTICIPANTS]                       [BOARDS] & [MATCH_FIXTURES]
  │                                        │
  │ (Assigned to match)                    │ (Officiated by)
  ▼                                        ▼
[MATCH_FIXTURES] 1 ───────────────────< [MATCH_OFFICIALS / REFEREES]
  │
  │ (Logs digital score sheet)
  ▼
[MATCH_SCORES]
1. users Table PK: user_id

user_id (PK), full_name, phone_number (Unique), email, role ('player', 'organizer', 'referee', 'help_desk'), created_at.

2. tournaments Table PK: tournament_id

tournament_id (PK), organizer_id (FK), title, venue_address, format (knockout/league), total_boards, max_points_per_set, boards_per_set, total_sets, entry_fee, status, verified_by_helpdesk (default false), created_at.

3. participants Table PK: participant_id

participant_id (PK), tournament_id (FK), user_id (FK), payment_reference_id (12-digit UTR), payment_status ('pending', 'approved', 'rejected'), seeding_rank, registered_at.

4. boards Table PK: board_id

board_id (PK), tournament_id (FK), board_number (1..N physical boards), is_active (boolean).

5. match_fixtures Table PK: fixture_id

fixture_id (PK), tournament_id (FK), round_number, board_id (FK), player_1_id (FK), player_2_id (FK), scheduled_start_time, match_status, winner_participant_id (FK).

6. match_officials Table PK: assignment_id

assignment_id (PK), fixture_id (FK), referee_user_id (FK -> users), assigned_at. Locks score-entry permissions exclusively to assigned officials.

7. match_scores Table PK: score_id

score_id (PK), fixture_id (FK), set_number, player_1_points, player_2_points, is_set_completed (boolean), set_winner_id, logged_by_referee_id, updated_at.

8. notification_logs Table PK: notification_id

notification_id (PK), fixture_id (FK), user_id (FK), recipient_phone, message, board_number, opponent_name, status, dispatched_at.

How These Relationships Power Your App Logic:
  • The 10-Minute Reminder: Background worker continuously checks match_fixtures where scheduled_start_time is 10 minutes away, notifying player_1 and player_2 with board # and opponent.
  • Referee Score Auditing: Checks match_officials to confirm referee_user_id matches assigned fixture before allowing writes to match_scores.
  • Live Audience Updates: Real-time WebSocket sync pushes instant scoreboard updates the moment is_set_completed flips to true.
